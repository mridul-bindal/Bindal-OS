MongoDB supports the four core data operations known as CRUD: create, read, update, and delete. Creating data usually means inserting one document with insertOne or several documents with insertMany. Each inserted document receives an _id if it does not already have one. Applications should validate input before insertion and may also enforce validation rules directly on the collection.

Reading documents is performed with find or findOne. A query filter selects documents by matching field values, comparison expressions, array contents, or nested fields. For example, a filter can select products whose price is greater than a threshold or users with a particular account status. A projection limits returned fields, reducing network transfer and preventing accidental exposure of sensitive data. Sorting, limiting, and skipping can shape result sets, though large skip values are not ideal for pagination.

Updating data uses updateOne, updateMany, or replaceOne. Update operators are especially important because they change only the intended fields. The $set operator assigns a value, $inc changes a numeric value, and $push appends to an array. A replacement overwrites the whole document except for its identifier, so it needs extra care. Upserts can create a new document when no existing document matches the filter.

Deleting uses deleteOne or deleteMany. Deletions should use precise filters and, for important information, teams may prefer a soft-delete field or archival process. MongoDB operations return result details such as matched and modified counts. Checking these results, handling errors, and using appropriate write concern help applications keep data changes dependable and visible.
