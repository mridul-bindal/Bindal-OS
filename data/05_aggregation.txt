MongoDB's aggregation framework processes documents through a sequence of stages called a pipeline. Each stage receives documents from the previous stage, transforms or filters them, and passes its output onward. Aggregation is useful for reporting, data cleanup, analytics, and creating application-specific views without moving data into a separate processing system.

The $match stage filters documents and should usually appear early in a pipeline so later stages process less data. The $project stage selects, reshapes, or computes fields. The $group stage combines documents by a key and calculates values such as totals, averages, minimums, maximums, or counts. The $sort, $limit, and $skip stages organize result sets. An $unwind stage expands array elements into individual pipeline documents, which is useful when calculating information about items inside an order.

More advanced stages include $lookup for combining documents from another collection, $set for adding calculated fields, and $facet for running multiple sub-pipelines at once. MongoDB expressions can perform conditional logic, date operations, string transformations, arithmetic, and array handling. Pipelines can be saved in application code, run interactively, or written to a collection with stages such as $merge.

Aggregation performance benefits from selective $match conditions and useful indexes. It is important to inspect pipeline results with representative data, because grouping and sorting large inputs can consume substantial resources. A readable pipeline, broken into purposeful stages, is easier to test and maintain than one large, opaque transformation.
